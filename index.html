路线总览

六个阶段按顺序推进，每个阶段以一个能交付的项目收尾。Prompt Engineering 不单独成段，放在阶段 1 学，之后每个项目都要用。另有一条并行的数学基础轨道（微积分 8 周，为概率论打基础），和主线同一天开始。

贯穿每个阶段的四条要求

带着问题学

每个知识点学完问自己：我能做出什么？怎样验证自己真的会了？每周的“自测”就是这个问题的具体版本。

每个项目至少 3 组 Prompt 对比

用同一组输入比较修改前后，记录改善了什么、有没有引入新的失败，再决定是否保留。README 写清 System Prompt 和约束的理由、是否用 Few-shot、怎样控制格式，以及怎样处理不确定、越界和格式错误的回答。

仓库就是证据

代码、文档、运行说明和测试都放进 GitHub。每个仓库回答五个问题：输入是什么，输出是什么，成功标准是什么，哪里容易失败，失败后怎样处理。

可以用 AI 学，结果自己验证

AI 帮你生成一段实现之后，亲手跑一个正常案例、一个异常案例，再试着讲清它的执行过程。

一周怎么安排（标准节奏）

  • 周一到周四，每晚 1.5–2 小时：读一个主题的文档，做对应的小实验
  • 周五，1 小时：回答本周自测题，写一页学习笔记
  • 周末，6–8 小时：完成“动手”任务；项目周全部用来写项目
  • 前 8 周加数学：每天再加 30–45 分钟微积分，每周 5 天，约 3 小时
  • 主线跟不上就在顶部切换节奏，日期会自动重排；数学轨道按自然周排，不受影响

从哪里开始

  • 已经会后端：直接从阶段 1 开始，模型基础和 API Playground 同时推进
  • 编程基础不稳：勾选“先补编程基础”，先做阶段 0
  • 别跳过后端：原文作者面试被指出工程能力不足，之后专门补了 MySQL 和计算机网络
